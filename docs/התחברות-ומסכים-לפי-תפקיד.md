## 1) סופר אדמין (`super_admin`)

| שאלה | תשובה |
|------|--------|

### מסכים/תפריטים שרואה (סרגל צד)

הנתיבים הם תחת `https://hotel-management-rho-two.vercel.app` + הנתיב בעמודה.

| סמל | מסך | נתיב |
|-----|------|------|
| סקירה | Overview | `/dashboard` |
| מלונות | רשימת כל המלונות + מלון חדש | `/dashboard/hotels`, `/dashboard/hotels/new` |
| משתמשים | ניהול משתמשים (כל המלונות) | `/dashboard/users`, `/dashboard/users/new`, `/dashboard/users/[id]` |
| אנליטיקה | גלובלי | `/dashboard/analytics` |
| יומן ביקורת | Audit logs | `/dashboard/logs` |
| צ׳קליסטים | תבניות צ׳קליסט | `/dashboard/checklists` |
| אוטומציות | משימות מתוזמנות | `/dashboard/automations` |
| בקשות אורחים | Guest requests | `/dashboard/guest-requests` |
| משובים | Guest feedback | `/dashboard/guest-feedback` |

בנוסף, מכל מלון אפשר להגיע לעריכה, חדרים, QR, פוסטר (לפי לינקי המלון ב־`LINKS.md`).

## 2) מנהל מלון (רמת מלון — `ceo` / `software_manager` / `hotel_admin`)

| שאלה | תשובה |
|------|--------|
| **איפה נכנס** | **אותו Admin Panel** כמו הסופר אדמין — ההבדל הוא **הרשאות ונתונים**, לא כתובת אחרת. |
| **URL התחברות** | https://hotel-management-rho-two.vercel.app/login |
| **אחרי התחברות** | `/dashboard` מציג נתונים **רק למלון שלו** (לפי `hotel_id` בפרופיל). |

### מסכים/תפריטים שרואה

**לא** רואה בניווט הראשי: רשימת כל המלונות, יומן ביקורת גלובלי, צ׳קליסטים גלובליים (בקוד הם מיועדים לסופר אדמין).

| סמל | מסך | נתיב (דוגמה) |
|-----|------|----------------|
| סקירה | Overview (מצומצם למלון) | `/dashboard` |
| המלון שלי | עריכת מלון + קישורים לחדרים/QR | `/dashboard/hotels/<hotel_id>` |
| משתמשים | רק עובדי המלון | `/dashboard/users` וכו׳ |
| אנליטיקה | קריאות למלון שלו | `/dashboard/analytics` |
| אוטומציות | למלון שלו | `/dashboard/automations?hotel_id=<hotel_id>` |
| בקשות אורחים | רק למלון שלו | `/dashboard/guest-requests` |
| משובים | רק למלון שלו | `/dashboard/guest-feedback` |

ניסיון כניסה ישיר ל־`/dashboard/hotels` (רשימה גלובלית) → **מפנה** לעמוד המלון שלו.

**הקמת מלון חדש** (`/dashboard/hotels/new`) — **לסופר אדמין בלבד**.

### מסכים אפשריים באפליקציה (מבנה ניתוב)

הנתיבים יחסיים ל־URL של ה־Staff App.

| מסך | נתיב | הערה |
|------|------|------|
| התחברות | `/login` | |
| בית / לוח בקרה | `/` | אחרי login |
| פתיחת קריאה חדשה | `/tickets/new` | לפי הרשאות במסך הבית |
| פרטי קריאה | `/tickets/:id` | |
| צ׳אט קריאה | `/tickets/:id/chat` | |
| ניהול חדרים | `/rooms/manage` | אם הותר לתפקיד |
| פרטי חדר | `/rooms/:id` | |
| אנליטיקה (מצומצמת) | `/analytics` | אם הותר |

**מה בפועל רואים** תלוי ב־`role` ובהרשאות ב־UI (לא כל עובד רואה את כל הנתיבים); זה **אותו אתר ואותו `/login`**.

## 4) מנהל תחנה / מנהל מחלקה (`dept_manager` — קבלה, אחזקה, משק בית, ביטחון…)

| שאלה | תשובה |
|------|--------|
| **איפה נכנס** | **אותו Staff App** כמו העובד — שוב, ההבדל הוא **תפקיד בפרופיל**, לא URL אחר. |
| **URL התחברות** | https://transcendent-mooncake-71c5b7.netlify.app/login |

### מסכים

אותה **רשימת נתיבים** כמו בסעיף 3. מנהל מחלקה בדרך כלל רואה:

- רשימת/ניהול קריאות **במסגרת המחלקה** שלו,
- אפשרויות הקצאה / אישור / סגירה (לפי מה שמומש ב־`HomeScreen` והזרימות),
- לעיתים **הוספת משתמש** (`/users/new`) אם הוזן בתפריט למנהלים.

אם מתכוונים ל־**מנכל/מנהל תוכנה** (ניהול מלון מלא מדפדפן) — זה **לא** Staff App אלא **מנהל מלון בסעיף 2**.

## הערה על `LINKS.md` הישן

ב־`LINKS.md` מופיעים שמות תפקידים ישנים (`hotel_manager`, `dept_manager` בפירוט אנגלי). בקוד ה־Admin הנוכחי התפקידים למנהלי מלון הם בעיקר **`ceo`**, **`software_manager`**, **`hotel_admin`** (ב־`lib/roles.ts`). ליצירת משתמשים מומלץ להשתמש בטפסים ב־**Admin → משתמשים** כדי שהערכים יהיו עקביים.
